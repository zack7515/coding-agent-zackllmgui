# 安全性與沙箱

這個資料夾放的是「這支程式能做到什麼、擋不住什麼」的完整說明。
單獨拉出來的理由：`run_shell` 會在你的機器上執行指令，
這件事的邊界不該散在 README 的功能清單裡讓人自己拼湊。

**一句話版本**：工具預設開著（只接受本機、每次都要你確認），
檔案工具擋得住，`run_shell` 擋不住，沒有沙箱。
要真的隔離，把整支服務放進容器（見下方「怎麼真的關起來」）。

---

## 1. 一共有幾道關卡

由外而內：

| # | 關卡 | 擋掉什麼 | 在哪 |
|---|---|---|---|
| 1 | 工具開關 | **預設開啟**；`--no-tools` 或網頁上關掉之後，一個工具定義都不會送給模型 | `ALLOW_TOOLS` |
| 2 | 只接受本機請求 | `--host 0.0.0.0` 時同網段的人不能叫你的機器跑指令 | `_is_local()` |
| 3 | 工作區路徑限制 | 檔案工具跑出專案資料夾 | `ws_path()` |
| 4 | 修改檔案要再開一道 | 讀得到不等於改得了 | `ALLOW_WRITE` |
| 5 | 指令風險判斷 | 無法還原的操作直接拒絕執行 | `command_risk()` |
| 6 | 每次執行前人工確認 | 上面全部漏掉時的最後一道 | 確認卡 |
| 7 | 改檔案與刪檔案前自動備份 | 改壞了、刪錯了還原得回來 | `.zackllmgui-backup/` |

第 6 道**關不掉到「完全不問」**，但有一格例外要講清楚：自動模式的
**「工作區內全自動」**會放行 ⚠ 風險指令中**動得到的路徑全部落在工作區裡**的那幾條
（`rm pkg/a.py`、`mv a b`、`chmod 755 x`），判斷在 `serve.py` 的 `ws_scoped()`。
其餘不變 —— ⛔ 級指令、`sudo`、裝套件、`git push`、`kill`、動到工作區外的路徑、
以及計畫核准，永遠要人看過。選這一格等於說「工作區裡的檔案壞了我認了，
反正有 git 跟 `.zackllmgui-backup/`」。

**沙盒開著時，這一格會放行所有 ⚠ 級指令**（`ws_scoped()` 直接回 `true`）。
理由是那時候「動不動得到工作區外」不必再從指令字串去猜：第 8 道把工作區以外
整台機器變成唯讀、憑證目錄用 tmpfs 蓋掉、網路斷掉，`pip install`、
`a && b`、`rm /etc/hosts` 全部在沙盒裡失敗。⛔ 那一級照樣拒絕執行 ——
它擋的是「跑起來就回不去」，跟能不能出得了沙盒是兩件事。

## 2. 擋得住什麼（有測試）

`tests/test_serve.py::test_workspace_jail` 逐條驗證：

```python
target = (root / raw).resolve()          # resolve() 會把 symlink 一起解開
if target != root and root not in target.parents:
    raise PermissionError(...)
```

| 手法 | 結果 |
|---|---|
| `../../etc/passwd`、`pkg/../../..` | 拒絕 |
| 絕對路徑 `/etc/passwd` | 拒絕 |
| `~/.ssh/id_rsa` | 拒絕 |
| 指向工作區外的 symlink | 拒絕（`resolve()` 之後才比對） |
| `.git`、`.venv`、`node_modules`、`__pycache__`、`dist` … | 拒絕 |
| `.env`、`*.env`、`*.pem`、`*.key`、`id_rsa*`、`*credentials*.json`、`.netrc` | 拒絕 |
| 把家目錄或磁碟根目錄設成工作區 | 拒絕（那等於沒有邊界） |

`ws_path()` 是**唯一**的入口，每個檔案工具都得先過它。
新增檔案工具時走這個函式，不要自己組路徑 —— 這是這份限制唯一的維護規則。

### 指令風險判斷

`command_risk()` 回傳 `("block" | "risky" | "ok", 原因)`：

| 等級 | 例子 | 行為 |
|---|---|---|
| ⛔ block | `rm -rf`、`rm /`、`mkfs`、`dd of=/dev/`、`> /dev/sda`、fork bomb、`shutdown`、`chmod -R 777 /`、`userdel`、`git push --force`、`curl … \| sh` | **拒絕執行**，`/tool` 與 `/run` 兩條路都擋 |
| ⚠ risky | `sudo`、`rm`、`pip/npm/apt install`、`git reset --hard`、`mv`、`chmod`、`kill` | 執行得了，但確認卡標紅講明原因，**自動模式一定會問人**——除了「工作區內全自動」那一格（沙盒開著時是整級放行），見上面第 6 道 |
| ok | `pytest`、`ls`、`git status`、`grep` | 照一般流程 |

判斷只寫在後端一份。前端曾經有一份自己的正規表示式，刪掉了 ——
風險判斷寫兩份時，過期的那份剛好會是決定跳不跳警告的那份。

被 block 的那一類的共同點：**備份救不回來**。
`rm` 掉工作區裡的檔案不在這一類（那個有 git 跟 `.zackllmgui-backup/`）。

## 3. 擋不住什麼

**`run_shell` 是所有限制的逃生口。** 講清楚：

| 以為擋得住 | 實際上 |
|---|---|
| 「工作區限制」 | 只管檔案工具。`run_shell` 的 cwd 是工作區，但 `cat /etc/passwd` 照跑 |
| 「不能裝套件」 | 能。實測時模型自己 `pip install pytest` 裝進了系統的 conda 環境 |
| 「金鑰檔讀不到」 | 檔案工具讀不到，`run_shell` 讀得到 |
| 「跑不出這台機器」 | 有網路，`curl` 想送去哪就送去哪 |

正面補救的部分：

- `setup_env` 給它一條只會動到工作區 `.venv` 的路，系統提示也明講「不要用 `run_shell` 下 pip」。
  這是降低誘因，不是關起來。
- `command_risk()` 擋掉最糟的那一類。
- 確認卡讓人看見它到底要跑什麼。

**沒有做**：白名單模式（只准 `python -m pytest`、`git status` 這幾條）。
做得到，但會犧牲掉大半實用性，目前判斷不划算。要做的話位置在 `_tool_run_shell()`。

## 3.5 允許規則：把判斷寫成規則

**允許規則**（`.zackllmgui-rules.json`）把「要不要放行」寫成規則。
`deny` 是在 `serve.py` 這一端擋的 —— 只在瀏覽器擋的話那不是邊界，是提醒。
`allow` **不能**解開 `command_risk()` 擋掉的指令，也不能讓風險指令變成不用問：
那條保證寫在文件上，不能被一個設定檔拿掉。

模型讀不到也寫不到這個檔案（`DENY_FILES` 收了 `.zackllmgui-*.json`）——
讀得到等於知道怎麼繞，寫得到等於自己給自己開權限。

### 曾經有過的 hooks，以及為什麼拿掉

早期版本有一份 `.zackllmgui-hooks.json`：工具前後跑使用者自己填的指令。
那是**整個專案裡風險最高的功能** —— 設定檔裡寫什麼就跑什麼，而且不用每次確認。
現在整個拿掉了，換成寫死的「改完自動 lint」（見 3.6），少一個執行入口。

## 3.6 改完自動檢查：唯一自動跑的外部指令

`write_file`／`edit_file` 成功之後會跑一次 linter。它是自動的、沒有開關，
所以邊界要靠寫死來守：

1. **指令是寫死的**，不是從設定檔讀的。只有 `ruff check` 與 `eslint`，
   使用者填不進第三支。
2. **只跑唯讀的檢查**，不跑會改檔案的格式化。在模型背後改掉檔案，
   它手上的內容就過期了。
3. **只在工作區裡跑**（`cwd` 是工作區，路徑也只給工作區內的檔案）。
4. **出任何事都吞掉**：linter 崩了、逾時了、不存在，都當作沒有檢查，
   絕對不會把已經成功的寫檔變成失敗。

擋不住的：**`eslint` 會載入專案自己的設定檔**，而 eslint 設定檔是可執行的
JavaScript。工作區裡有惡意的 `.eslintrc.js` 就等於有一段會被執行的程式碼。
這跟「在別人的 repo 裡跑 `npm test`」是同一種風險，沙盒開著的話它也一樣關在裡面。

## 4. 怎麼真的關起來

兩種做法，對應兩種不同的威脅 —— 混在一起講就會得出「容器不安全」這種假結論：

| 威脅 | 做法 | 誰來做 |
|---|---|---|
| **`serve.py` 本身被攻破** | 整支服務放進容器 | 使用者，從外面 |
| **模型做了蠢事或危險的事** | 只把 `run_shell` / `run_tests` 丟進容器 | `serve.py` 自己 |

第二種**已經接上了**，實作在 [`../sandbox/`](../sandbox/README.md)：介面上是
「功能與工具 → 沙盒執行」，或啟動時加 `--sandbox`。**預設關**。

**一個作業系統一種做法**（開啟時會偵測跑 `serve.py` 的那一台）：

| 平台 | 後端 | 擋住什麼 | 實測 |
|---|---|---|---|
| Linux | bubblewrap | 工作區以外唯讀、憑證目錄蓋掉、無網路 | ✅ 全部通過，每次多 7 ms |
| macOS | 內建 `sandbox-exec` | 工作區以外不能寫、無網路（**讀取不擋**） | ⚠️ 沒有機器，未實測 |
| Windows | Docker Desktop | 只掛得到工作區、無網路、資源上限 | ⚠️ 沒有機器，未實測 |
| 跨平台 | docker / podman | 同上 | ✅ 全部通過，每次多 176 ms |

核心層的做法排在容器前面，因為它不換掉檔案系統 —— pytest、node、gcc、CUDA
都還在原地，而容器裡「映像檔沒裝的就是沒有」。

`run_shell`、`run_tests`、`setup_env` 都會被包進去，**三支裡只有 `setup_env` 開網路**
（pip 一定要連得出去，開放範圍就縮在裝套件那一步）。

自己驗一遍 —— 這些檢查是真的執行指令去看結果，不是讀設定猜的：

```bash
python -m sandbox                      # 逐項驗證 + 量開銷
python -m sandbox --backend=container
```

**邊界要講清楚的一點**：Linux 的做法蓋掉的是**憑證目錄**（`.ssh`、`.aws`、`.gnupg`、
`.kube`、`.docker`、雲端 CLI 的設定），不是整個家目錄。一開始是整個蓋掉的，
結果 `run_tests` 直接爆掉 —— 這台的 python 在 `~/miniconda3`，conda、pyenv、nvm、
cargo 也全在家目錄底下，蓋掉等於蓋掉整套工具鏈。所以邊界是**家目錄讀得到但寫不動**
（整個 `/` 都是唯讀掛進去的），配上斷網 —— 讀得到的東西也送不出去。

在意讀取的話用 `--sandbox container`：那個換掉整個檔案系統，家目錄根本不存在。

第一種永遠是使用者自己決定，從**外面**做：

```bash
podman run --rm -it \
  -v "$PWD:/work:rw" \
  -p 127.0.0.1:5678:5678 \
  --network=host \
  python:3.13-slim \
  python /work/serve.py --host 0.0.0.0 --workspace /work
```

（`--network=host` 是為了連得到宿主機的 Ollama；不需要 Ollama 時拿掉，
改 `--network=none` 就是完全斷網。）

**為什麼不做在 `serve.py` 裡**：一支程式如果沙箱是它自己開的，
那道牆就在它自己手上 —— 真正的隔離必須在它上面一層。
把 `bwrap` / `firejail` 包在 `run_shell` 外面也一樣：
擋得住老實的指令，擋不住「先寫一個腳本再叫別人跑」，屬於看起來安全而已。

## 5. 從別台機器使用時

三種模式的安全含意不一樣：

| 模式 | 誰的機器在跑指令 | 風險 |
|---|---|---|
| 各自跑各自的 `serve.py`，`--ollama` 指向遠端 GPU（**唯一推薦**） | 自己的 | 跟單機用一樣 |
| 共用一個網址 + `--trust-remote` | 伺服器的 | **連得到網頁的人都能在伺服器上執行指令** |

第一種之所以是唯一推薦：瀏覽器碰不到使用者自己的硬碟，
所以「共用網址」不管怎麼設計，大家改的都是伺服器上的檔案。
`serve.py` 是單一檔案、零相依，複製到自己機器上跑的成本低到沒有理由不這麼做。

（曾經做過第三種：網頁在遠端、工具打回自己那台的 `serve.py`，靠
`--allow-origin` 白名單開跨來源。做完發現它解的問題，第一種本來就解了，
而且還多一個「哪個網頁能指揮我的 shell」的攻擊面。整套刪掉了。）

`--trust-remote` 沒有預設值以外的緩衝：它就是把第 2 道關卡整個關掉。
啟動時會印一行警告，這是刻意的。

## 6. 回報問題

發現可以繞過上面任何一條的方法，開 issue 之前先確認：
是不是 `run_shell` 造成的？如果是，那不是繞過 —— 那是第 3 節寫明的已知限制。
其他的（尤其是檔案工具跑出工作區、或不用確認卡就執行到東西）請直接回報，
並附上重現用的 `pattern` / `path` / `command`。
