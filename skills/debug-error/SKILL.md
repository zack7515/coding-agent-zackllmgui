# 從錯誤訊息找原因

## 步驟

1. **先讀完整個 traceback，從最底下往上看。** 最後一行是症狀，
   倒數第二段才通常是原因所在的那個檔案。
2. `read_file` 讀出事的那幾行（帶前後文，不要只讀一行）。
3. 問自己「**什麼樣的輸入會走到這一行**」，然後回頭找那個輸入從哪來。
   `search_files` 找呼叫端。
4. **重現它。** `run_tests` 或 `run_shell` 跑一次，看到一樣的錯誤再動手。
   重現不了就先說出來，不要猜著改。
5. 改一個地方，再跑一次。
6. 修好之後補一個會抓到這個 bug 的測試 —— 不然它會回來。

## 判斷準則

- **症狀不是原因。** `NoneType has no attribute x` 的修法不是加 `if x is not None`，
  是去找「為什麼這裡會是 None」。加了判斷只是把錯誤推到更遠的地方。
- 同一個錯誤訊息連續出現兩次，代表方向錯了，不是改得不夠多。停下來重新讀一次。
- 「改了就好了但我不知道為什麼」要講出來，那通常代表還沒修好。

## 常見的假原因

| 看起來像 | 通常其實是 |
|---|---|
| 編碼錯誤 | 讀檔沒指定 encoding |
| 找不到模組 | 跑的 python 不是裝套件的那一個（用 `setup_env` 建 .venv） |
| 偶爾才錯 | 有共用狀態或順序相依 |
| 只有 CI 會錯 | 依賴了本機才有的檔案或環境變數 |

## 什麼時候不要用這個

錯誤訊息已經明講怎麼修的時候（例如「請先安裝 X」）。直接做就好。
