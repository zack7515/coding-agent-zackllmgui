# 解釋程式碼

## 步驟

1. 先確定範圍。使用者指了檔案就 `read_file` 那個檔；只給了函式名就先
   `search_files` 定位，再讀那一段 —— **不要整個檔案讀進來**。
2. 這段程式碼呼叫到的東西也要看一眼（`search_files` 找定義），
   不然解釋會停在「它呼叫了 foo()」這種等於沒說的層次。
3. 照這個順序講：
   - **一句話說它負責什麼**
   - **輸入什麼、輸出什麼、有什麼副作用**（改檔案？發網路請求？改全域狀態？）
   - **不明顯的地方為什麼要那樣寫** —— 這才是使用者真正在問的
   - **可疑的地方**（沒處理的例外、寫死的值、看起來會壞的邊界）
4. 引用位置用 `檔名:行號`，讓使用者點得過去。

## 判斷準則

- **不要逐行翻譯成中文。** 「這一行把 x 設成 1」沒有任何價值，
  使用者看得懂語法，他看不懂的是意圖。
- 看到奇怪的寫法先假設它有理由，去找那個理由（註解、git log、呼叫端），
  找不到再說「這裡看起來可以簡化，但我沒找到不能簡化的原因」。
- 超過 200 行的東西不要一次解釋完，先給架構圖再問要深入哪一塊。

## 什麼時候不要用這個

使用者要的是修改而不是理解的時候。那種情況直接讀完就動手，
先講一大段解釋只是拖時間。
