# 跑測試並修到通過

## 步驟

1. **先跑 `run_tests`，不要先猜。** 沒有錯誤訊息之前的所有推論都是浪費。
2. 訊息說 `No module named pytest` 之類的缺套件，用 `setup_env`
   （`packages: ["pytest"]`）裝進工作區的 `.venv`。
   **不要用 `run_shell` 下 `pip install`**——那會裝進系統環境。
3. 看 `assert` 那一行：左邊是實際值、右邊是期望值。先確定「哪個函式回傳了錯的東西」，
   再用 `read_file` 讀那個函式，不要整個檔案讀進來。
4. 用 `edit_file` 改一個地方，`old` 要含縮排且在檔案裡唯一。
5. 再跑一次 `run_tests` 確認。**沒有再跑一次就不算修好。**

## 判斷準則

- **測試失敗時修的是程式，不是測試。** 真的認為測試寫錯了，先說出來讓使用者決定，
  不要自己改測試讓它變綠。
- 一次只改一個地方。連續改兩處之後測試還是紅的，你會分不出是哪一處的問題。
- 同一個錯誤訊息連續出現兩次，代表你的修法方向錯了，不是改得不夠多。

## 什麼時候不要用這個

專案沒有測試的時候。那種情況該先問使用者要不要補測試，
而不是自己開始寫一堆 `test_*.py`。
