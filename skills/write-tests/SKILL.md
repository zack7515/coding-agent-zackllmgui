# 補測試

## 步驟

1. `read_file` 讀要測的東西，**先確認它現在的行為是對的**。
   對著壞掉的程式寫測試，只會把 bug 固定下來。
2. `list_dir` / `search_files` 找現有的測試，照**同一套寫法**寫：
   同樣的檔名慣例、同樣的斷言風格、同樣的 fixture。
   這個專案沒有測試框架就別自己引一個進來。
3. 每個測試只驗一件事，名字要說得出它在驗什麼
   （`test_add_rejects_negative` 而不是 `test_add_2`）。
4. 先寫**會失敗的那一種**：邊界、空值、例外路徑。
   happy path 通常已經被別的地方間接測到了。
5. `run_tests` 跑起來。缺套件用 `setup_env`，不要 `pip install`。
6. **新寫的測試要先確認它真的會失敗過** —— 把被測的程式暫時改壞、跑一次看它紅，
   再改回來。永遠不會紅的測試等於沒有測試。

## 判斷準則

- 不要為了覆蓋率而測。測一個 getter 回傳它自己設的值，那是在測 Python 不是測你的程式。
- 不要 mock 到只剩下 mock 在互相驗證。真的很難測就說出來，那通常代表設計要調整。
- 測試裡不要有邏輯（迴圈、if）。有 if 的測試壞掉時你分不出是程式錯還是測試錯。

## 什麼時候不要用這個

專案完全沒有測試而且使用者只是想改一個小 bug 的時候。
那種情況先問「要不要順便建測試架構」，不要自己開始鋪一整套。
