# 子代理型別

一種子代理是一個 `.md`，不是一段程式碼 —— 加一種不必改 `serve.py`。
工作區裡也可以放一個 `agents/`，同名時工作區的那份贏（規則跟 `skills/` 一樣）。

```markdown
---
name: 型別名稱，模型在 task 的 type 參數填這個
description: 一行說明，會直接送進工具定義的 enum 描述裡
tools: read_file, list_dir      # 逗號分隔；寫 * 代表「除了永遠不給的以外都給」
isolation: worktree             # 留空＝跟主代理共用工作區
model:                          # 留空＝跟主代理同一個模型
---

這裡是這種子代理的系統提示。
```

**唯讀是靠 `tools` 擋的，不是靠提示詞求它別寫。** 想要一種只能讀的子代理，
就在 `tools` 裡只列讀類工具。而且擋在**兩層**：網頁不把沒列到的工具定義送給它，
`serve.py` 的 `agent_guard()` 再擋一次 —— 就算模型幻覺出一個工具名硬叫，也叫不動。
只有前者的話「唯讀」只是提示詞層級的承諾。

兩支工具**永遠不給**，寫在 `tools` 裡也沒用：`ask_user_question`（子代理問了也沒人
看得懂上下文，該問就寫進結論讓主代理去問）與 `todo_write`（待辦是主代理那條線的東西，
子代理寫進去會把它的清單蓋掉）。

`task` **給不給看你怎麼寫**：列進 `tools`（或寫 `*`）的型別可以自己再開子代理，
深度上限 2 層。這一點照 Claude Code 的做法 —— 它的 `Explore` 與 `Plan` 工具清單裡
沒有 `Agent`，`general-purpose` 有，所以「能不能開下一層」是**每一種自己宣告的**，
不是全域禁止。差別在它用提示詞當成本煞車（有人在看帳單），這裡放著跑沒人看，
所以是硬的深度上限。
